2
Paper ingestion & RAG pipeline
Week 3–5 · Fetch papers, chunk text, embed, store — the core of everything
Core skill ›
What you'll build
  • ArXiv API client: search by keywords, download PDFs, extract metadata (title, authors, abstract, references)
  • PDF parser using PyMuPDF or pdfplumber — extract text per section (Abstract, Methods, Results)
  • Chunking strategy: recursive character splitter with 512-token chunks + 64-token overlap
  • Embedding pipeline: batch-embed chunks using OpenAI text-embedding-3-small or a local model
  • Vector DB insertion: upsert chunks with metadata (paper_id, section, page) as payload
  • Retrieval endpoint: given a query string, return top-k relevant chunks with scores
Primary stack
LangChain (loaders, splitters) ArXiv Python API PyMuPDF Qdrant (Docker, local) OpenAI embeddings
Low-RAM alternatives
ChromaDB (in-process, no Docker) sentence-transformers/all-MiniLM (free local embeddings, ~100 MB) Qdrant in-memory mode (no persistence disk writes)
Prefer OpenAI's embedding API over local models for now — saves 1–2 GB RAM for actual agent logic later.
3
Multi-agent system with LangGraph
Week 6–9 · The most impressive part of your resume — agentic orchestration
Resume highlight ›
Agents to build (one at a time)
  • Planner agent — receives a research query, decomposes it into sub-tasks, routes to specialist agents
  • Retriever agent — queries ArXiv API + your vector DB, returns top papers and relevant chunks
  • Extractor agent — reads a paper and extracts: problem statement, methods, datasets, results, limitations
  • Comparator agent — given N extracted paper summaries, identifies agreements, contradictions, gaps
  • Writer agent — synthesizes everything into a literature review section with proper citations
  • Future-work agent — identifies open problems and suggests 3–5 research directions
LangGraph concepts to master
  • StateGraph: defining nodes (agents/tools) and edges (transitions) as a typed state machine
  • Conditional edges: routing based on agent output (e.g., "need more papers" → back to Retriever)
  • Checkpointing: persist state so you can resume a long research run
  • Human-in-the-loop: pause graph and ask for confirmation before expensive LLM calls
Stack
LangGraph LangChain OpenAI GPT-4o-mini Pydantic (structured outputs)
Low-cost alternatives
Groq API (fast, cheap Llama 3) Ollama + Mistral 7B (fully local, ~5 GB RAM) Avoid loading >1 local model at a time on 8 GB
4
Memory & citation graph
Week 10–12 · Long-term memory + Neo4j graph — advanced differentiation
Differentiator ›
Memory system (3 tiers)
  • In-context memory — current session state passed through LangGraph nodes (already done in Phase 3)
  • Episodic memory — store past research sessions as summaries in vector DB, retrieve when topic recurs
  • Semantic memory — structured facts (paper → method → dataset → metric) stored in Neo4j as a knowledge graph
Citation graph with Neo4j
  • Parse reference lists from PDFs using GROBID (free, Docker) or regex on reference sections
  • Create nodes: Paper(arxiv_id, title, year), Author(name), Venue(name), Method(name)
  • Create edges: CITES, WRITTEN_BY, PUBLISHED_IN, USES_METHOD, IMPROVES_UPON
  • Query: "find all papers that cite BERT and also use contrastive learning"
  • Detect influential papers by in-degree (PageRank) and research clusters by community detection
Stack
Neo4j Desktop (free) py2neo or neo4j Python driver GROBID (Docker) LangChain Neo4j integration
RAM-saving approach
Neo4j Desktop (local, ~512 MB idle) NetworkX + SQLite as lighter alternative (no Docker) Don't run Neo4j + Qdrant + Ollama simultaneously
5
Evaluation, async & optimization
Week 13–16 · What separates a project from an engineering portfolio piece
Engineering depth ›
Evaluation (critical for placement interviews)
  • RAG eval: retrieval precision@k, recall@k using a hand-labelled 20-paper test set
  • Generation eval: RAGAS framework — faithfulness, answer relevancy, context precision
  • Agent eval: task completion rate, number of LLM calls per research query (cost proxy), latency
  • Build an eval dashboard (even a simple CSV + matplotlib) — shows you care about metrics
Async pipeline
  • Use Python asyncio + aiohttp for concurrent ArXiv fetches (10x faster than sequential)
  • Batch embedding calls: send 100 chunks per OpenAI API call instead of 1 per call
  • Use Celery + Redis for background paper ingestion (papers get processed while agent is running)
  • Rate limiting: respect ArXiv's 3-req/sec limit with asyncio.Semaphore
Retrieval optimization
  • Hybrid search: combine BM25 (keyword) + vector similarity scores with RRF (Reciprocal Rank Fusion)
  • HyDE: generate a hypothetical answer first, embed it, then retrieve — often beats vanilla RAG
  • Re-ranking: use Cohere Rerank API or a cross-encoder model to reorder top-20 results to top-5
  • Query expansion: LLM generates 3 paraphrases of the query; retrieve for all 3, then deduplicate
Stack
RAGAS asyncio + aiohttp Celery + Redis BM25 (rank_bm25) Cohere Rerank (free tier)

UI, deployment & portfolio packaging
Week 17–20 · Make it demonstrable in an interview in under 2 minutes
Placement-ready ›
Frontend (simple, don't over-engineer)
  • Streamlit app: research query input → real-time agent progress stream → literature review output
  • Show the citation graph as an interactive network using pyvis or streamlit-agraph
  • Side panel: show retrieved papers with relevance scores, expandable chunks
  • Export button: generate a Markdown or PDF literature review
Deployment (free tier friendly)
Docker Compose (local demo) Streamlit Cloud (free, public) Railway (free $5 credit/month) Render (free tier)
GitHub / portfolio checklist
  • README with architecture diagram, demo GIF, and a one-paragraph "how it works" section
  • System design doc (1 page) explaining your agent orchestration decisions — interviewers love this
  • Eval results section: show your RAGAS scores and what you did to improve them
  • Write a dev.to or Medium post about one interesting technical challenge you solved (e.g., HyDE, hybrid search)
  • .env.example file with all env vars documented — shows professional habits
